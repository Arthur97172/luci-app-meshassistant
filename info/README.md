# MESH助手详细配置指南

简体中文 | [English](README.en.md)

本文介绍 luci-app-meshassistant 的完整组网方法：如何选择角色和地址、节点或客户端在什么情况下需要静态 IP、有线与无线回程如何配合，并给出 2–3 台无线路由器组网的完整示例。插件的基本安装与功能概览见[项目主页](../README.md)。

> 本文中的所有操作都对应页面上的实际字段和脚本的真实行为。命令只用于查看状态或应急恢复；日常配置请在 LuCI 页面完成。

## 1. 组网前的准备

### 1.1 硬件与固件

- 每台设备运行 OpenWrt / ImmortalWrt 24.10 或 25.12，并使用 JavaScript 版 LuCI。
- 安装 `luci-app-meshassistant`，以及 `kmod-batman-adv`、`batctl-default`、`luci-proto-batman-adv`、`kmod-cfg80211`、`dawn`、`bash`。
- 至少有一个支持 802.11s Mesh 的无线射频。推荐双频设备：一个射频做普通 AP，另一个射频专用于 Mesh 回程，避免普通 WiFi 与回程争抢同一射频的空中时间。

### 1.2 规划拓扑

组网前先在纸上确定四件事：

| 项目 | 说明 |
| --- | --- |
| 角色 | 一个 Mesh 中只有一台「服务器」，其余为「节点」；「客户端」与「节点」的实际行为相同 |
| 管理地址 | 服务器地址、每台节点的地址、子网掩码、网关、DNS |
| Mesh 射频 | 所有设备使用同一个射频（例如 `radio0` 或 `radio1`） |
| 回程方式 | 纯无线；或部分设备之间使用专用有线回程 |

### 1.3 备份配置

在每台设备上通过 SSH 备份关键配置：

```sh
mkdir -p /root/mesh-backup
cp /etc/config/network /etc/config/wireless /etc/config/dhcp \
   /etc/config/firewall /etc/config/system /root/mesh-backup/
```

插件自身也会在启用时备份它修改的 LAN、主机名、DHCP 设置，并在关闭 Mesh 时恢复；额外的手工备份用于应对断电、误操作或需要重新刷机的情况。

### 1.4 管理连接建议

应用设置时脚本会重启网络和无线。建议：

- 用网线连接到一台**不会**被移出 LAN 网桥的端口进行配置；
- 不要通过即将被修改的 WiFi 或即将被设为有线回程口的端口管理设备；
- 节点改成静态 IP 后，如果当前正通过旧地址访问，浏览器会断开，需要改用新地址重新登录。

## 2. 页面字段与配置流程

入口：**网络 → MESH助手**（英文界面 **Network → Mesh Assistant**）。

### 2.1 基础设置

| 字段 | 作用 |
| --- | --- |
| 启用 Mesh 网络 | 总开关。保存并应用后还要点击「重新应用 MESH助手设置」才会真正生效。 |
| Mesh 模式 | 服务器 / 节点 / 客户端。 |
| 服务器提供 DHCP | 仅服务器显示。开启时由服务器提供 DHCP 和 IPv6 RA；LAN 上已有其他 DHCP 服务器时关闭。 |
| WiFi 网络 SSID | 普通 WiFi 接入点的名称。 |
| 普通 AP 射频 | 承载普通 WiFi 的射频。可从 2.4 GHz、5 GHz、6 GHz 中选择最多两个射频，所选射频使用同一个 WiFi 网络 SSID；6 GHz 按 WPA3 启动。 |
| 启用 MLO | 仅当普通 AP 射频选中两个射频时显示。开启后两个射频合并为一个 Wi-Fi 7 多链路接入点，所选射频自动切换为 EHT 模式（MLO 要求所有链路均为 802.11be）。 |
| Mesh 射频 | 承载 Mesh 回程的射频，单选。所有设备必须选同一个射频。 |
| 有线回程端口 | 可选。选择与另一台 Mesh 设备相连的 LAN 网桥端口；纯无线回程保持「无」。 |
| Mesh 网络 SSID | Mesh 回程的标识，所有设备必须完全一致。实际 802.11s 的 `mesh_id` 会自动加上 `-mesh` 后缀，例如填写 `MyMesh` 时空中看到的是 `MyMesh-mesh`。 |
| 密码保护 / Mesh 密码 | 开启后普通 AP 使用 WPA3 混合模式，Mesh 回程使用 WPA3；密码至少 8 位。所有设备必须一致。 |

> 所有设备的 **Mesh 射频**、**Mesh 网络 SSID**、**密码保护** 和 **Mesh 密码** 必须完全一致，否则邻居不会出现。

### 2.2 AP 模式（仅节点 / 客户端）

| 字段 | 作用 |
| --- | --- |
| 节点主机名 | 建议使用 `node2` – `node9`（也可自定义），写入系统主机名，便于在 DHCP 租约和 SSH 中识别。每台节点应不同。 |
| IP 模式 | `DHCP`：节点 LAN 作为 DHCP 客户端；`Static`：使用下面填写的静态地址。节点本身**不提供** DHCP。 |
| 静态 IP 地址 | 节点 LAN 地址，必须与服务器/网关同网段且不冲突。 |
| Mesh 网关 IP 地址 | 节点的默认网关，通常填服务器的 LAN 地址；DHCP 复用拓扑中填实际上网主路由的地址。 |
| IPv4 子网掩码 | 与服务器/主路由一致，常见为 `255.255.255.0`。 |
| DNS 服务器 | 通常填服务器的 LAN 地址；也可以填上游主路由或公共 DNS。 |
| 启用哑 AP 模式 | 把节点改成接入现有网络的哑 AP，会更换管理地址，操作前有确认对话框。详见[第 5 节](#5-哑-ap-模式)。 |

这些设置不只在哑 AP 模式下生效：普通启用节点时，脚本也会应用 IP 模式和主机名，并在关闭 Mesh 时恢复原来的 LAN 与主机名。

### 2.3 高级设置

K/V/R、移动域（4 位十六进制）和 RSSI 阈值用于漫游优化。除非了解 802.11k/v/r 和 `dawn` 的行为，否则保持默认值。所有设备的移动域应保持一致。

### 2.4 保存与应用

1. 点击页面底部的「保存并应用」——这一步只写入 `/etc/config/meshassistant`，不改网络。
2. 点击「重新应用 MESH助手设置」——脚本才真正创建/删除接口、修改 LAN、启动或停止服务。执行输出写入 `/tmp/meshassistant.log`。
3. 建议顺序：**先服务器，后节点**。服务器先形成 Mesh 网关，节点加入后才能正常工作。
4. 应用过程中网络和无线会重启，页面可能短暂断开；等待重启完成后重新连接并刷新页面。

## 3. 节点 / 客户端何时需要静态 IP

### 3.1 先理解「节点的 IP 模式」

节点和客户端不提供 DHCP，也不做 NAT。它们关闭 `firewall`、`dnsmasq`、`odhcpd`，只把 `bat0` 加入 `br-lan`，通过 Mesh 与服务器二层互通。

「IP 模式」决定的是**节点自己的管理地址从哪里来**：

- **DHCP**（默认）：脚本把节点 LAN 设为 DHCP 客户端。节点必须能在 Mesh LAN 上找到一台 DHCP 服务器，通常是：
  - 服务器角色且「服务器提供 DHCP」为开启；
  - 或者 LAN 上已有的其他路由器。
- **Static**：脚本把节点 LAN 设为静态地址，并使用你填写的地址、掩码、网关和 DNS。

### 3.2 建议使用静态 IP 的情况

| 情况 | 原因 |
| --- | --- |
| Mesh LAN 上没有 DHCP 服务器 | 服务器关闭了「服务器提供 DHCP」，且没有其他主路由。DHCP 模式下节点拿不到地址，会失去管理入口。 |
| 需要稳定的管理地址 | 书签、SSH、监控、端口转发、远程访问都希望节点地址固定。 |
| 需要区分多台节点 | 给节点分配 `.2`、`.3`、`.4` 等固定地址，比在租约表里找地址更直观。 |
| DHCP 地址池较小或经常变化 | 避免节点地址变化导致失联。 |
| 哑 AP 部署 | 哑 AP 通常应使用固定管理地址，方便主路由和用户访问。 |
| 排错 | 当 DHCP 异常导致节点失联时，静态地址可以减少变量。 |

### 3.3 可以继续使用 DHCP 的情况

- 服务器开启了「服务器提供 DHCP」，且节点能通过 Mesh 获取地址；
- 或者 LAN 上有稳定的主路由 DHCP 服务器；
- 你不需要固定地址，愿意在服务器的 DHCP 租约表中查找节点。

DHCP 模式下，可以在服务器的 LuCI「状态 → DHCP 租约」查看节点地址，也可以在服务器 SSH 中查看 `/tmp/dhcp.leases`。节点主机名（`node2`、`node3` 等）通常也会出现在租约中，便于识别。

### 3.4 静态 IP 的填写规则

以服务器 LAN 为 `192.168.10.1/24` 为例：

| 字段 | 示例 | 规则 |
| --- | --- | --- |
| IP 模式 | Static | — |
| 静态 IP 地址 | `192.168.10.2` | 与服务器同网段、唯一、未被其他设备占用；建议放在 DHCP 地址池之外，或在 DHCP 服务器上添加静态租约。 |
| Mesh 网关 IP 地址 | `192.168.10.1` | 服务器的 LAN 地址（DHCP 复用拓扑中填实际上网主路由地址）。 |
| IPv4 子网掩码 | `255.255.255.0` | 与服务器/主路由一致。 |
| DNS 服务器 | `192.168.10.1` | 服务器的 LAN 地址；也可以填上游主路由或公共 DNS。 |
| 节点主机名 | `node2` | 每台节点唯一。 |

> 页面默认值是 `192.168.8.3` / `192.168.8.1`，这只是示例，**必须改成你实际 LAN 的地址**。如果服务器的 LAN 是 `192.168.10.1` 而节点填了 `192.168.8.3`，节点将无法被访问。

### 3.5 静态 IP 常见错误

| 错误 | 后果 | 正确做法 |
| --- | --- | --- |
| 地址不在服务器同网段 | 节点与 Mesh LAN 三层不通，页面失联 | 使用与服务器相同的子网 |
| 地址与其他设备冲突 | 间歇性断网、ARP 冲突 | 选择空闲地址或配置静态租约 |
| 网关填成节点自己或错误地址 | 节点无法访问管理网络/互联网 | 网关填服务器或上游主路由 |
| 掩码与服务器不一致 | 部分设备不可达 | 与服务器保持一致 |
| 忘记修改默认 `192.168.8.x` | 节点失联 | 按实际 LAN 修改 |
| 静态地址落在 DHCP 池内 | DHCP 可能把同一地址分配给其他设备 | 使用池外地址或静态租约 |

### 3.6 服务器也需要固定地址

服务器的「AP 模式」标签页不显示，服务器不会通过该页修改 LAN。请在启用 Mesh 前，先在 **网络 → 接口 → LAN** 中把服务器 LAN 设为静态地址（例如 `192.168.10.1`），并配置好网关/DNS。否则服务器地址可能随上游 DHCP 变化，节点里填写的网关也会失效。

## 4. 有线回程配置方法

有线回程是可选的，三种角色都支持，按设备单独配置。

### 4.1 前提条件

- 网线两端都必须是运行本插件的 Mesh 设备，并都在「有线回程端口」中选择相连的端口。
- 所选端口必须是 **LAN 网桥端口**，不能是 WAN 口，也不能已被其他逻辑接口占用。
- 不要把管理端口或普通 LAN 上行端口选为有线回程口——该端口会从 LAN 网桥移出，专用于 Mesh 回程。
- 两端端口名可以不同（例如一端 `lan3`、另一端 `lan4`），只要物理网线连接的是各自选中的端口即可。

### 4.2 配置步骤

1. 在设备 A 的「有线回程端口」中选择连接设备 B 的 LAN 口（例如 `lan3`）。
2. 在设备 B 的「有线回程端口」中选择连接设备 A 的 LAN 口（例如 `lan4`）。
3. 用网线连接这两个端口。
4. 保存并应用，然后分别点击「重新应用 MESH助手设置」。

脚本会把端口从 `br-lan` 移出，创建 `network.mesh_wired`（`batadv_hardif`，`master=bat0`，MTU 1500），并设置很高的吞吐量覆盖值，使 BATMAN_V 在网线连通时优先走有线。

### 4.3 自动切换

有线 hardif 和无线 hardif 会同时保留：

- 网线连接时：BATMAN_V 优先使用有线回程；
- 网线拔出时：有线 hardif 变为 down，流量自动切换到 Mesh 无线；
- 网线恢复时：自动切回有线。

切换由 BATMAN_V 的链路探测完成，不需要手动操作。前提是**两端都预先选好了端口**；脚本不会自动发现一根随便插上的 LAN 网线。

### 4.4 注意事项

- 如果只有一端选择了有线回程端口，另一端仍把该口当普通 LAN 口使用，则不会形成 Mesh 有线回程，而且选择端口的设备会失去该口的普通 LAN 功能。
- 有线回程口不再承载普通 LAN 流量。需要普通有线上行时，把「有线回程端口」保持为「无」，按普通 LAN 口使用。
- 网线另一端如果是主路由、交换机或未运行本插件的设备，不要在本插件中选择有线回程端口；那只是普通 LAN 连接。
- 脚本不会处理 `bridge-vlan`（VLAN 过滤）配置。使用 VLAN 的设备在启用有线回程前应手动确认端口归属。
- 更换端口或关闭 Mesh 时，脚本会把旧端口还原到 LAN 网桥。

## 5. 哑 AP 模式

「启用哑 AP 模式」用于把节点接入一个已经存在、由其他路由器负责 DHCP 的网络，使其只作为无线接入点工作。

操作前请确认：

- 你接受管理地址改变，并知道新地址；
- 你能通过网线或新地址重新访问设备；
- 该网络已有 DHCP 服务器（通常是主路由）。

点击按钮后会先弹出确认对话框，再次确认后才执行。脚本会：

- 备份 `wireless`、`network`、`dhcp`、`system`、`firewall` 到 `/etc/config/*.meshbak`；
- 停用 `firewall`、`dnsmasq`、`odhcpd`；
- 把 LAN 改成「AP 模式」中填写的静态地址，或改为 DHCP 客户端；
- 删除 `wan` / `wan6`，把 WAN 端口并入 `br-lan`；
- 调整防火墙区域、关闭 LAN DHCP，并写入主机名。

恢复方法：

```sh
bash /meshassistant/meshassistant.sh undumb
```

脚本会把当前配置移到 `/etc/config/*.dumbap` 留作参考，恢复 `*.meshbak`，并重新启用相关服务。

> 哑 AP 是破坏性操作：管理地址、WAN 和防火墙都会改变。操作前请备份配置，并确保你能物理接触到设备。

## 6. 验证与排错

### 6.1 页面状态

应用完成后刷新页面，顶部「Mesh 状态」显示：

- 活动节点数；
- 邻居节点、接口、邻居及其下游客户端的 IP 地址和最后发现时间。

如果显示「无法读取 Mesh 状态」，说明 `batctl` 缺失或执行失败，而不是邻居数为 0。

### 6.2 常用检查命令

在设备 SSH 中执行：

```sh
# 查看 Mesh 邻居
batctl n

# 查看本机 Mesh 配置
uci show meshassistant

# 查看 BATMAN 接口
ip -4 addr show br-lan
iw dev

# 查看最近一次应用日志
cat /tmp/meshassistant.log

# 查看系统日志
logread | tail -50
```

### 6.3 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 两边都启用了 Mesh，但邻居数为 0 | Mesh 射频、Mesh 网络 SSID 或密码不一致；设备距离过远；射频不支持 802.11s | 逐项核对三台设备的 Mesh 射频、SSID、密码；拉近距离测试 |
| 节点页面打不开 | 静态地址不在同网段、地址冲突、没有 DHCP 服务器、哑 AP 改了地址 | 查看服务器 DHCP 租约；检查节点配置；必要时通过网线/串口/恢复模式处理 |
| 客户端连上 WiFi 但拿不到 IP | 服务器关闭了「服务器提供 DHCP」，且 LAN 上没有其他 DHCP 服务器 | 打开服务器 DHCP，或让主路由提供 DHCP |
| 有线回程没有生效 | 只有一端选了端口；端口不是 LAN 网桥口；网线未插好；端口被 WAN 占用 | 两端都选端口；查看 `/tmp/meshassistant.log`；改用 LAN 网桥端口 |
| 有线连接时仍走无线 | 网线断开/协商失败；两端未同时配置；端口被移出网桥后对端不是 Mesh 设备 | 检查网线、两端配置和日志 |
| 关闭 Mesh 后地址变了 | 脚本恢复了启用前的 LAN 地址，这是预期行为 | 用原地址重新登录 |
| 节点上的防火墙/DHCP 服务不见了 | 节点会停用 `firewall`、`dnsmasq`、`odhcpd`，这是 Mesh 节点的正常行为 | 关闭 Mesh 或改回服务器角色后会自动恢复 |

### 6.4 日志中的关键信息

`/tmp/meshassistant.log` 会记录：

- 创建/删除的无线接口；
- LAN 地址和主机名变更；
- 有线回程端口的移出与还原；
- 端口校验失败、回退到无线回程等告警。

排错时先看这个文件，再结合 `batctl n` 和 `logread`。

## 7. 组网示例

下面三个示例都假设设备是 W1700K 或类似的双频路由器，Mesh 射频为 `radio0`（5GHz/6GHz），普通 AP 射频为 `radio1`。实际射频名称以页面下拉框为准。

### 示例一：两台路由器，纯无线回程

适合首次组网、出租屋或小户型：一台服务器 + 一台节点，全部通过无线回程。

```text
[互联网]
   │ WAN
[路由器 A：服务器 192.168.10.1]
   │
   ~~~~ 5GHz Mesh 无线回程（SSID：MyMesh-mesh）~~~~
   │
[路由器 B：节点 192.168.10.2]
```

**路由器 A（服务器）**

| 字段 | 值 |
| --- | --- |
| 启用 Mesh 网络 | 开启 |
| Mesh 模式 | 服务器 |
| 服务器提供 DHCP | 开启 |
| WiFi 网络 SSID | `HomeWiFi` |
| 普通 AP 射频 | `radio1` |
| Mesh 射频 | `radio0` |
| 有线回程端口 | 无 |
| Mesh 网络 SSID | `MyMesh` |
| 密码保护 | 按需开启，密码所有设备一致 |
| LAN 地址 | 先设为 `192.168.10.1/24` |

**路由器 B（节点）**

| 字段 | 值 |
| --- | --- |
| 启用 Mesh 网络 | 开启 |
| Mesh 模式 | 节点 |
| WiFi 网络 SSID | `HomeWiFi`（可与 A 相同，也可不同） |
| 普通 AP 射频 | `radio1` |
| Mesh 射频 | `radio0` |
| 有线回程端口 | 无 |
| Mesh 网络 SSID | `MyMesh` |
| 密码保护 / Mesh 密码 | 与 A 完全一致 |
| 节点主机名 | `node2` |
| IP 模式 | Static |
| 静态 IP 地址 | `192.168.10.2` |
| Mesh 网关 IP 地址 | `192.168.10.1` |
| IPv4 子网掩码 | `255.255.255.0` |
| DNS 服务器 | `192.168.10.1` |

**操作顺序**

1. 先把 A 的 LAN 设为 `192.168.10.1`，接好 WAN 上行。
2. 在 A 上填写并保存，点击「重新应用 MESH助手设置」。
3. 在 B 上填写并保存，点击「重新应用 MESH助手设置」。
4. 等待无线重启，分别打开两台设备的「Mesh 状态」，应看到对方为邻居。
5. 用手机连接 `HomeWiFi`，应能获取 `192.168.10.x` 地址并上网。

> 如果 B 改用 IP 模式 `DHCP`，它会从 A 获取地址；此时可在 A 的「DHCP 租约」中查找 `node2` 的地址。需要稳定地址时仍建议使用静态 IP。

### 示例二：三台路由器，服务器 + 两台节点，混合回程

适合复式、两层楼或长条形户型：服务器与其中一台节点用网线回程，另一台节点用无线回程；三台设备共同组成一个 Mesh。

```text
[互联网]
   │ WAN
[路由器 A：服务器 192.168.10.1]（客厅）
   │ lan3（专用有线回程）
   │
[路由器 B：节点 192.168.10.2]（书房）
   │
   ~~~~ 无线 Mesh（可经 B 中继）~~~~
   │
[路由器 C：节点 192.168.10.3]（卧室）
```

**A（服务器）**

- Mesh 模式：服务器；服务器提供 DHCP：开启。
- Mesh 射频 `radio0`，Mesh 网络 SSID `MyMesh`，密码与 B/C 一致。
- 有线回程端口：选择连接 B 的 LAN 口（例如 `lan3`）。
- 普通 AP 射频：`radio1`；LAN 地址：`192.168.10.1`。

**B（节点）**

- Mesh 模式：节点；Mesh 射频 `radio0`；Mesh 网络 SSID `MyMesh`；密码一致。
- 有线回程端口：选择连接 A 的 LAN 口（例如 `lan3`；端口名不必与 A 相同）。
- 节点主机名：`node2`；IP 模式：Static；地址 `192.168.10.2`；网关 `192.168.10.1`；掩码 `255.255.255.0`；DNS `192.168.10.1`。
- 注意：`lan3` 被专用于回程后不再承载普通 LAN；管理 B 请使用无线或另一个 LAN 口。

**C（节点）**

- Mesh 模式：节点；Mesh 射频 `radio0`；Mesh 网络 SSID `MyMesh`；密码一致。
- 有线回程端口：无（纯无线）。
- 节点主机名：`node3`；IP 模式：Static；地址 `192.168.10.3`；网关 `192.168.10.1`；掩码 `255.255.255.0`；DNS `192.168.10.1`。
- C 可以直接与 A 通信；如果距离较远，BATMAN 会自动经 B 中继。

**验证**

- 在 A 上执行 `batctl n`，应看到 B（有线接口）和 C（无线接口）的邻居，或至少看到可达的邻居。
- 拔掉 A–B 网线，B 应自动改用无线回程；重新插上后自动恢复有线优先。
- 三台设备的「Mesh 状态」都应显示活动节点，客户端在三台设备之间漫游时应保持连接。

### 示例三：已有主路由提供 DHCP（DHCP 复用）

适合家里已有一台主路由负责拨号和 DHCP，另外用 2–3 台 Mesh 设备扩展覆盖。这里用三台 Mesh 设备：A 为服务器，B、C 为节点；主路由不运行本插件。

```text
[互联网]
   │
[主路由 192.168.5.1：PPPoE + DHCP + IPv6 RA]
   │ LAN
   │
[路由器 A：服务器 192.168.5.2]（Server Provides DHCP = 关闭）
   │
   ~~~~ 无线 Mesh（SSID：MyMesh-mesh）~~~~
   │
[路由器 B：节点 192.168.5.3]   [路由器 C：节点 192.168.5.4]
```

**主路由**

- 保持现有设置，继续提供 DHCP 和 IPv6 RA。
- 不要在主路由上启用第二个 DHCP 服务器。

**A（服务器）**

| 字段 | 值 |
| --- | --- |
| Mesh 模式 | 服务器 |
| 服务器提供 DHCP | **关闭** |
| Mesh 射频 | `radio0` |
| Mesh 网络 SSID | `MyMesh` |
| 密码保护 / Mesh 密码 | 与 B、C 一致 |
| 普通 AP 射频 | `radio1` |
| LAN 地址 | `192.168.5.2/24`，网关/DNS 指向主路由 `192.168.5.1` |
| 有线回程端口 | 若 A–B 使用有线回程，选择连接 B 的专用 LAN 口；连接主路由的网线必须使用另一个仍留在网桥中的 LAN 口 |

A 的 LAN 地址需要在 **网络 → 接口 → LAN** 中提前设置好；「AP 模式」标签页对服务器不显示。

**B、C（节点）**

| 字段 | B | C |
| --- | --- | --- |
| Mesh 模式 | 节点 | 节点 |
| Mesh 射频 | `radio0` | `radio0` |
| Mesh 网络 SSID | `MyMesh` | `MyMesh` |
| 密码 | 与 A 一致 | 与 A 一致 |
| 节点主机名 | `node2` | `node3` |
| IP 模式 | DHCP 或 Static | DHCP 或 Static |
| 静态地址（如选 Static） | `192.168.5.3` | `192.168.5.4` |
| 网关（如选 Static） | `192.168.5.1` | `192.168.5.1` |
| 掩码 | `255.255.255.0` | `255.255.255.0` |
| DNS（如选 Static） | `192.168.5.1` | `192.168.5.1` |

**说明**

- B、C 选择 `DHCP` 时，会从主路由获取 `192.168.5.x` 地址；选择 `Static` 时使用上表地址，便于管理。
- 如果希望 Mesh 客户端使用 A 上的 DNS/过滤服务（例如 OpenClash / OxiDNS），把节点的网关和 DNS 改为 `192.168.5.2`，并确保 A 能把流量转发到主路由。否则保持 `192.168.5.1` 即可。
- A 连接主路由的网线只是普通 LAN 上行：不要把连接主路由的端口选为「有线回程端口」；若 A–B 使用有线回程，请选择另一对专用 LAN 口。
- A 与 B 之间的专用网线才是本插件的有线回程：两端都选专用端口后连接，不要经过主路由。
- 只能有一台 DHCP 服务器。A 的「服务器提供 DHCP」必须关闭，否则会与主路由冲突。

## 8. 关闭、回滚与恢复

### 8.1 正常关闭 Mesh

1. 关闭「启用 Mesh 网络」。
2. 点击「保存并应用」，再点击「重新应用 MESH助手设置」。

脚本会删除 Mesh/AP 接口、删除 `bat0` 和 `mesh_batman`、把有线回程端口还原到 `br-lan`，并恢复启用前的 LAN 地址、主机名、DHCP/RA 设置和由它停用的服务。

### 8.2 恢复哑 AP

```sh
bash /meshassistant/meshassistant.sh undumb
```

### 8.3 应急恢复

如果配置错误导致无法通过 LuCI 访问：

- 尝试用网线连接设备的 LAN 口，在服务器 DHCP 租约中查找设备地址；
- 如果知道静态地址，把电脑设为同网段地址后直接访问；
- 检查 `/tmp/meshassistant.log` 和 `logread`（需要 SSH 或串口）；
- 恢复 `/root/mesh-backup/` 中的配置，或使用 OpenWrt 的 failsafe 模式；
- 哑 AP 模式可用 `undumb` 恢复五份配置。

> 任何改动前保留备份，并确保能物理接触到设备，是避免“变砖”的最有效方法。
